# クリーンルーム5択ドリル（消化器）

医学教育モデル・コア・カリキュラムと医師国家試験出題基準に対応づけた5択問題を、ブラウザだけで解いて、自動採点と解説を受けられるサイトです。

**使ってみる**：https://hm-cmed.github.io/cleanroom-mcq/

- インストールもアカウント登録も要りません。解答の記録はブラウザの中だけに保存され、外部には送られません。
- 1問ごとに採点し、5つの選択肢すべてに「正しい記述か・誤った記述か」と、その根拠（事実カードと出典）を表示します。模擬試験のように最後にまとめて解説を見ることもできます。
- 途中でやめるときは、成績表（CSV）と再開用ファイル（JSON）を保存できます。同じブラウザなら自動で続きから再開できます。
- 結果は領域別・出題基準の項目別に集計し、間違えた問題だけを解き直せます。

## クリーンルーム方式

問題は、教科書やガイドラインの文章を写さずに作ります。

1. 論文・ガイドラインから事実と数値だけを取り出し、自分の言葉で「事実カード」に書く（[cleanroom-gi-facts](https://github.com/hm-cmed/cleanroom-gi-facts)）。出典の実在とライセンスを API で照合する。
2. 問題の各選択肢に、その正誤を決める事実カードを1枚ずつ対応させる。
3. `tools/build.py` が、選択肢と事実カードを機械的に突き合わせる（カードの有無・廃止・出典照合の状態・数値の一致）。
4. 専門医が監修し、承認した問題だけを「監修済み」として公開する。

解説の文章は事実カードの主張文をそのまま使います。問題ファイルに解説を手で書かないので、カードを直せば解説も直ります。医師国家試験の過去問題は使いません。

## フォルダ

| 場所 | 中身 |
|---|---|
| `index.html` `js/app.js` `css/style.css` | サイト本体（ビルド不要の静的ファイル） |
| `js/config.js` | 表示の設定（名前、開発者、監修前の問題を出すか、助成の表記） |
| `items/*.yaml` | 問題の原本（人が編集する） |
| `tools/build.py` | 問題を事実票と照合し、`data/questions.js` を作る |
| `data/questions.js` | サイトが読む問題データ（自動で作る。直接編集しない） |
| `reports/check_report.md` | 照合の結果（エラーと、監修のときに見る注意点） |

## 問題の書き方

```yaml
- id: Q-LV-001            # Q-<領域>-<3桁>。一度付けたIDは使い回さない
  ask: true               # true＝「正しいのはどれか」、false＝「誤っているのはどれか」
  stem: 肝硬変の腹水について正しいのはどれか。
  options:                # 必ず5つ。正答は ask と truth が一致する1つだけ
    - {text: （選択肢の文）, truth: true,  fact: LV-006}
    - {text: （選択肢の文）, truth: false, fact: LV-010}
    # …
  status: draft           # draft（監修前）/ approved（監修済み）/ retired（廃止）
  # approved にするときは reviewer（監修者）と reviewed_at（日付）を書く
```

- `fact` には、その選択肢が正しい・誤っていると言える根拠のカードIDを書きます。
- 正しい選択肢に入れる数字は、カードの主張文にある数字と一致させます（違うとビルドが止まります）。
- 誤りの選択肢で数字を変えた場合は「注意」として報告されます。意図したものか監修で確認してください。
- 正答の根拠になるカードは、出典の照合が済んだもの（`verified_sources` 以上）に限ります。

## 問題データを作り直す

事実票のレポジトリを隣に置いて実行します（Windows の PowerShell）。

```powershell
git clone https://github.com/hm-cmed/cleanroom-gi-facts ..\cleanroom-gi-facts
pip install pyyaml
python tools\build.py
```

エラーが0件なら `data/questions.js` が更新されます。

## 監修の進め方

1. `reports/check_report.md` の「注意」と、サイトで実際に解いた画面を見ながら、問題文・選択肢・解説を確認する。
2. 問題がなければ、その問題の `status` を `approved` にし、`reviewer` と `reviewed_at` を書く。
3. 監修済みの問題がそろったら、`js/config.js` の `showDrafts` を `false` にすると、監修前の問題は出題されなくなる。
